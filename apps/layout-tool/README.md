# <img src="docs/logo.svg" alt="" height="44" align="top"> Layout-Tool

An interactive web application for designing railway track layouts on a map: the first module of
[Rail-Across-Suite](../../README.md), in its repository under `apps/layout-tool/`, running in the suite at
[railacross.open-layout-tool.org/layout/](https://railacross.open-layout-tool.org/layout/). It was the
Open-Layout-Tool before it became a module of the suite.

## Features

- **Interactive map** with multiple basemaps (OpenStreetMap, Elevation, Satellite) based on MapLibre, plus an
  overlay for the German rail network's kilometrage lines
- **Create track elements** — create new track from scratch using straight lines and curves, or as elements
  parallel to existing tracks
- **Connect elements** — link to other elements using curves, straight lines, and transition curves
  (clothoid, Bloss)
- **Switches**, to form the foundation of a train station or whatever the requirements may be, including
  switches laid into existing tracks across straights, curves and clothoids, and switch connections between two tracks
- **Splice elements** — connect two track elements with a matching track element
- **Edit elements** — modify geometry, elements and switches
- **Platforms** — create platforms
- **Plan export** — scaled site plans (1:500 / 1:1000) as PDF or SVG, with main points, stationing, element
  labels, switch symbols, kilometrage, a title block and an optional map backdrop
- **Data exchange** — import/export full projects or selected tracks as JSON, import Verm.ESN surveying data,
  and export to [OSRD](https://osrd.fr) format
- **Project management** — projects with variants and revisions on a project server, users with sign-in;
  or, in the local version, projects in the browser alone

## Getting Started

```bash
npm install         # here or at the repository root: one workspace for the whole toolkit
npm run data        # the NTv2 grids, by version and SHA-256 (data.json)
npm run dev
```

The NTv2 grids and the kilometrage lines are not in the repository (`data.json`). `npm run data` fetches the
grids; the kilometrage lines are not published — whoever has them puts them into `tiles/`, and `npm run data`
links them into the app.

The dev server runs over HTTPS (with a self-signed certificate, which the browser will warn about once).
It forwards `/api` to the project server ([`server/`](../../server/README.md)) and `/optimizer` to the
optimizer service ([`services/optimizer/`](../../services/optimizer/README.md)); see the suite's
[`deploy/README.md`](../../deploy/README.md) for running both locally. Signing in and the users are the
suite's: sign in on its sign-in page (`apps/home`), or the tool says where to sign in.

## Local version

The same codebase also builds a version that runs in the browser alone — no server, no sign-in, the
projects kept in the browser's storage, with export and import as files (Paket L). It holds only the
browser components (`src/core`); what needs the project server or the optimizer service (`src/server`)
is left out of its bundle.

```bash
npm run local       # build it and serve it on http://localhost:8080/
npm run local:zip   # the same as a zip to hand on: app, a small server (Node.js 18+), start scripts
```

What it can and cannot do: [`tools/local/README.md`](tools/local/README.md) — the README in the zip.

## Running a server

The Layout-Tool is a module of Rail-Across-Suite and runs on the suite's server: the start page at the
root, this app under `/layout/`, the project server with the one sign-in behind both. The suite's
[`deploy/`](../../deploy/README.md) sets it all up from one configuration file.
